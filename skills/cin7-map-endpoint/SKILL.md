# Map a missing endpoint

Structure only: names, verbs, parameter and body key names, a response type. No values, no cookies, no records.

## Hand-edited or generated

| File | Kind |
|---|---|
| `data/endpoints.csv` (internal `/api/*` and controller actions) | **Hand-edited source.** No script in this repo writes it. Columns: `url,kind,effect,methods,params,body_keys,reader_root,n_fields,sections,pages,bundles`. Keep it sorted by `url`. |
| `data/pages.csv` | Hand-edited source: routes, section, menu label, bundles. |
| `data/wms-api.csv`, `mes-api.csv`, `pos-api.csv`, `report-service-endpoints.csv` | Hand-edited sources for the other front ends. |
| `data/public-api.csv`, `data/public-api-shapes.json` | Built from Cin7's published API Blueprint with `tools/apib_shapes.py`. Public API gaps are not fixed here. |
| `data/ui.json` | Built by `tools/extract_ui.js` from page bundles. |
| `tools/front_ends/*.md` | Hand-written prose for modules 20 to 25. |
| `modules/**`, `docs/RELATIONSHIPS.md` | **Generated by `python3 tools/generate.py`.** It deletes every folder under `modules/` first: never edit them. |
| `README.md`, `docs/INTERNAL-API.md` and the other `docs/` | Hand-written. Counts in them do not update themselves. |
| `cin7-core-cli/src/cin7_cli/spec.json` | Generated by `scripts/build_spec.py`. Never edit. |

## 1. Check it is really missing

```bash
grep -i 'ProductionOrder' data/endpoints.csv | cut -d, -f1-4
```

The button may call a URL already listed (a print action, a `Download…` link, an `/api/…_AutoPick` read). Match by URL, not by label. `cin7 ops --source web <text>` in cin7-core-cli searches the same rows.

## 2. Capture (guide the person; do it in their browser)

1. Open the page in DevTools, Network tab. Tick **Preserve log** and clear it.
2. Click the button once. For a form POST that downloads a file, the request is the one with a document or file response.
3. Right-click the request, **Copy as cURL**, or save a HAR. Keep either **outside the repo** (a temp folder) and delete it afterwards.
4. Read from it only: method, path without host or query values, query and form field **names**, JSON body **keys**, `Content-Type` of the request, and the response `Content-Type` and its top-level array key.

## 3. Strip before saving anything

- Drop `Cookie`, `Set-Cookie`, `Authorization`, `X-` tokens and anything that looks like a key. Chrome's sanitized HAR export removes some; check the result anyway.
- Replace every id, name, SKU, order number, tenant id and email with nothing: the map holds names, not values. The `_dc` timestamp parameter is not recorded.
- Never paste the cURL, HAR or a response body into the repo, an issue or a PR. Search your diff for `eyJ`, `Bearer`, `cookie` and `@` before committing.

## 4. Record it

Add or edit one row in `data/endpoints.csv`, in `url` order:

| Column | What to put |
|---|---|
| `url` | Path only, e.g. `/ProductionOrder/PrintPickList`. |
| `kind` | `api` for `/api/…`, `mvc` for a controller action. |
| `effect` | `read`, `write`, `read+write` or `read (may log an audit line)`. A print is the last one, or `write` if unsure. |
| `methods` | Space-separated: `GET`, `POST`, `GET(navigate)`, `POST(read)` for a POST that only queries, or the `REST(GET read; POST/PUT/DELETE on store.sync)` form for ExtJS stores. |
| `params` / `body_keys` | Space-separated names: query and form fields, JSON body keys. |
| `reader_root` | The array key a list comes back under (`{root: [...], total}`), else empty. |
| `sections`, `pages`, `bundles` | Use values already in other rows: a section name from `SECTIONS` in `tools/generate.py`, routes from `data/pages.csv`, the page's bundle. |

The CSV has no column for request encoding or response type. Say them in the PR description. If they change how a client must call it (form-encoded versus JSON, file versus JSON), also add a line to `docs/INTERNAL-API.md` or the matching `tools/front_ends/*.md`.

## 5. Regenerate and check

```bash
python3 tools/generate.py
git diff --stat          # only modules/ README files that list this URL, plus counts
```

Re-running on unchanged data produces no diff, so any other change is yours. Update hand-written counts in `README.md` if they moved.

Then in cin7-core-cli, with the rebuild repo checked out beside it:

```bash
python scripts/build_spec.py ../cin7-core-rebuild
pytest -q          # includes test_spec_matches_rebuild_repo_when_present
cin7 ops --source web PrintPickList
```

New rows appear under `web-<module>` groups. They are sendable only when `effect` starts with `read` and `methods` has a GET (or `POST(read)`), and the name avoids words like `print`, `delete`, `release`, `send`. Print actions with a name ending `/Print…` also show up in `cin7 print where`.

## Rules

1. **Never send a captured write request to test it.** No replay, no cURL, no "just once". Record it and mark `effect` as `write`.
2. **No tenant data** in `data/`, commits, PR text or screenshots. Invented examples only.
3. **Don't edit generated files**, and don't commit a regenerated `modules/` that differs in places you did not touch.
4. **One row per URL.** If it is listed, extend its `params` or `pages`. Unsure about `effect` means `write`; the CLI then refuses to send it.

## When it fails

| Symptom | Cause |
|---|---|
| Endpoint missing from `modules/…/README.md` | `sections` does not match a name in `SECTIONS`, so it landed in `15-other`. |
| `build_spec.py` puts it in the wrong group | Its URL is not in any module README: regenerate first. |
| `test_spec_matches_rebuild_repo_when_present` fails | `spec.json` was not rebuilt after the data change. |
